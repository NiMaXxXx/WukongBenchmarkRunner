# Wukong Benchmark Runner

Консольный инструмент на C# (.NET 8) для автоматического запуска **Black Myth: Wukong Benchmark Tool** из Steam.
Он выполняет два прохода, CPU-тест и GPU-тест, каждый со своим набором настроек. После каждого прохода
он забирает и разбирает файл результата бенчмарка и формирует отчёт: характеристики ПК, результаты обоих
тестов и использованные настройки.

Весь сценарий проходит без участия человека: от запуска инструмента до отчёта.

## Быстрый старт

**Что нужно**

- Windows 10/11 и [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0);
- Steam и установленный [Black Myth: Wukong Benchmark Tool](https://store.steampowered.com/app/3132990/) (бесплатный);
- бенчмарк хотя бы **один раз запущен вручную до главного меню**. При первом запуске он показывает выбор языка,
  настройку яркости и политику конфиденциальности. Согласие на сбор данных — решение пользователя, поэтому
  инструмент его не принимает и при непройденном первом запуске остановится с подсказкой.

**Запуск**

```bash
git clone <ссылка на репозиторий>
cd WukongBenchmarkRunner
dotnet run -c Release
```

Оба теста занимают около 8 минут. **Пока они идут, не трогайте мышь и клавиатуру:** инструмент управляет
меню бенчмарка через эмуляцию ввода.

**Параметры**

| Параметр | Назначение |
| --- | --- |
| `--only cpu` / `--only gpu` | выполнить только один тест |
| `--game-dir <путь>` | папка бенчмарка, если не нашлась через Steam |
| `--output <папка>` | куда сохранить отчёт (по умолчанию `./results`) |
| `--no-rt` | не включать полную трассировку лучей в GPU-тесте |
| `--keep-settings` | не возвращать исходные настройки бенчмарка после тестов |

## Что получается на выходе

Отчёт печатается в консоль и сохраняется в `results/<дата_время>/`:

| Файл | Содержимое |
| --- | --- |
| `report.md` | отчёт в Markdown: характеристики ПК, результаты, настройки и их обоснование |
| `report.json` | те же данные в машиночитаемом виде |
| `cpu_raw.json`, `gpu_raw.json` | исходные файлы результата от бенчмарка |
| `GameUserSettings.original.ini` | резервная копия настроек бенчмарка до запуска |

Пример отчёта с реального прогона: [docs/sample-report.md](docs/sample-report.md).

В отчёт входят:

- **ПК:** процессор, видеокарта (видеопамять, драйвер), оперативная память (объём, частота, модули),
  материнская плата, ОС, монитор, накопитель с бенчмарком, схема электропитания;
- **результаты** каждого теста по данным бенчмарка: средний, минимальный и максимальный FPS, 5-й перцентиль,
  видеопамять, загрузка GPU. По посекундной телеметрии (`Records`) дополнительно считаются 1% low, среднее
  время кадра на CPU и GPU, занятость GPU и узкое место;
- **настройки** каждого теста. Значения, которые бенчмарк сам записал в файл результата, отмечены ✓:
  так видно, что игра действительно применила заданные настройки.

## Выбор настроек

### CPU-тест: убрать видеокарту из уравнения

| Настройка | Значение | Зачем |
| --- | --- | --- |
| Разрешение экрана | 1280×720 (минимальное) | меньше пикселей — меньше работы GPU |
| Апскейлер / масштаб рендера | TSR, 33 % | кадр рендерится примерно в 423×238 |
| Набор настроек графики | все пункты «Низкое» | минимум нагрузки на GPU |
| Генерация кадров | выкл. | дорисованные кадры завышают FPS и скрывают предел CPU |
| Полная трассировка лучей | выкл. | самая тяжёлая для GPU функция |
| VSync / лимит FPS | выкл. | FPS не должен упираться в искусственный предел |

Почти вся работа видеокарты растёт с числом пикселей: шейдинг, освещение, постобработка. При рендере
в ~423×238 эта работа почти исчезает, а логику, анимацию, физику и подготовку кадров (draw calls)
процессор выполняет в том же объёме. TSR выбран, потому что работает на видеокартах любого производителя
и позволяет задать масштаб рендера напрямую. У DLSS, FSR и XeSS режимы фиксированные.

**Проверка на i7-12700F + RTX 4060 Ti:** видеокарта занята рендером лишь около 57 % времени кадра, остальное
время ждёт процессор. Это подтверждает, что узкое место — CPU.

### GPU-тест: нагрузить видеокарту по максимуму

| Настройка | Значение | Зачем |
| --- | --- | --- |
| Разрешение экрана | родное разрешение монитора | максимум пикселей |
| Апскейлер / масштаб рендера | TSR, 100 % | рендер в полном разрешении, без апскейла |
| Набор настроек графики | все пункты «Кинематографичное» | максимальное качество |
| Полная трассировка лучей | вкл., уровень «Ультра» | path tracing — самая тяжёлая для GPU функция |
| Генерация кадров | выкл. | иначе половина кадров дорисовывается, и FPS не отражает реальный рендер |
| Размытие в движении | «Очень заметное» | дополнительный проход постобработки |
| VSync / лимит FPS | выкл. | видеокарта не должна простаивать в ожидании лимита |

Полная трассировка лучей доступна только на NVIDIA RTX. На других видеокартах инструмент её не включает,
это видно по названию GPU. Отключить вручную можно параметром `--no-rt`.

**Проверка на той же машине:** видеокарта занята 98 % времени кадра, загрузка GPU 98 %.

## Как это работает

1. **Поиск бенчмарка.** Путь к Steam берётся из реестра, затем по `libraryfolders.vdf` находится библиотека
   с `appmanifest_3132990.acf` и папка установки.
2. **Настройки.** Бенчмарк хранит настройки в `<папка бенчмарка>\b1\Saved\Config\Windows\GameUserSettings.ini`:
   - строка `UISettingData`: значения пунктов меню;
   - секция `[ScalabilityGroups]`: те же качества в шкале движка (`sg.* = значение − 1`).

   Кодировку значений я выяснил, переключая каждую опцию в меню и сравнивая файл до и после:

   | Ключ `UISettingData` | Значения |
   | --- | --- |
   | `QualityLevel`, `ViewDistance`, `ShadowQuality`, … | 1 «Низкое» … 5 «Кинематографичное» |
   | `SuperResolutionSampling` | 0 FSR, 1 XeSS, 2 DLSS, 3 TSR |
   | `ImageQuality` | высота рендера в пикселях (= высота × масштаб) |
   | `ScreenResolution`, `WindowFullImageQuality` | индекс в списке разрешений и масштаб окна × 10⁶ |
   | `InsertFrame` / `Rtx` | генерация кадров / полная трассировка: 0 или 1 |
   | `RtxLevel` | 1 «Низкий», 2 «Средний», 3 «Ультра» |
   | `MotionBlur` | 0 выкл., 1 малозаметное, 2 очень заметное |

   Настройки записываются, пока игра закрыта: некоторые из них, например трассировка, применяются только
   при запуске. Исходный файл сохраняется и в конце возвращается на место, даже при ошибке или Ctrl+C.
3. **Запуск теста.** Игра запускается через `steam://rungameid/3132990`. Параметров командной строки для
   автостарта теста у бенчмарка нет, а главное меню не реагирует на стрелки клавиатуры, только на мышь
   и геймпад. Поэтому инструмент:
   - ставит курсор на пункт «Тест быстродействия» и нажимает **E** («Подтвердить»);
   - нажимает **E** ещё раз в диалоге «Хотите запустить тест быстродействия?».

   Перед каждым шагом инструмент проверяет **яркость пикселей** в нужной точке окна: подсвеченный пункт
   и кнопка диалога — светлые плашки на тёмном фоне. Проверка не зависит от языка интерфейса, в отличие
   от OCR. Координаты сняты на окне 1920×1080 и масштабируются по высоте окна, как сам интерфейс UE.
4. **Результат.** После прохода бенчмарк пишет JSON в `%TEMP%\b1\BenchMarkHistory\Tool\<unix-время>`
   (без расширения). Инструмент ждёт появления нового файла, проверяет, что JSON читается целиком,
   закрывает игру и разбирает результат.

## Ограничения

- Игра запускается на основном мониторе в режиме «Окно без рамок». Координаты меню проверены на 16:9;
  на ультрашироких мониторах их, возможно, придётся поправить в `src/Automation/MenuLayout.cs`.
- Во время тестов окно игры должно оставаться на переднем плане, поэтому мышь и клавиатуру трогать нельзя.
  Если фокус всё же уйдёт, инструмент попробует вернуть его сам.
- Проверено на: i7-12700F, RTX 4060 Ti 8 ГБ, 32 ГБ DDR4-3200, Windows 11 25H2, бенчмарк 1.0.3.14649.

## Структура проекта

```
src/
  Program.cs                   сценарий: поиск → характеристики → два прохода → отчёт
  Options.cs                   параметры командной строки
  Steam/SteamLocator.cs        поиск Steam и бенчмарка
  SystemInfo/                  характеристики ПК (WMI, реестр, WinAPI)
  Settings/
    BenchmarkProfiles.cs       настройки CPU- и GPU-теста с обоснованием
    SettingsWriter.cs          запись настроек в GameUserSettings.ini
    IniFile.cs, UiSettingData.cs   разбор INI и строки UISettingData
  Automation/
    BenchmarkSession.cs        запуск, старт теста из меню, ожидание результата
    MenuLayout.cs              координаты элементов меню
    ScreenSampler.cs           яркость области экрана (GDI)
    GameWindow.cs, Input.cs    окно игры, эмуляция мыши и клавиатуры (SendInput)
  Results/                     модель файла результата и производные метрики
  Report/ReportBuilder.cs      отчёт в Markdown
```
